the L3 header is more complecated than the L2 header made with 



	1/ version (4 bits)

identifies the version of ip used 

	0100 -> 4 , for ipv4
	0110 -> 6 , for ipv6 

ipv5 was made for experiment , but was never published

when the value is for IPv6 the whole header changes (in a different video)



	2/ IHL - Internet Header Length (4 bits)

the last field (options) is variable in Length , so we need a way to keep track of the header Length

the IHL has an increment of 4 bytes(one line in the previous chart)

  so if  the value is 5 ---> 5 x 4 = 20 bytes (minimum length without Options)    actual value of  0101 
the maximum value is 15 --> 15 x 4 = 60 bytes                                     actual value of  1111



	3/ DSCP - Defferentiated Services code Point (6 bits)

used for QoS - Quality of Service (another video)

the field is used t oprioritize delay-sensetive data (Streaming Voice, video, ...)



	4/ ECN - Explecit Congestion Notification (2 bits)

provide end-to-notification of Network congestion witout dropping packets
(congestion is busy with traffic) usualy dropping packets

is an optiona field that requires both ends and Network infrastructure to support it



	5/ Total Length (16 bits)

the Length of the whole packet (L3 header and L4 Segment)

minimum size is 20 (only header)   00000000 00010100

maximum size is 65535              11111111 11111111



	6/ identification (16 bits) 

if a packet is fragmented this number is used to identify which packet this fragment belongs to 

all fragments must have the same number

the packet gets fragmented if it passes the MTU (maximum Transmition unit)

the MTU is usually 1500 bytes (in L2PDU ,if packet length is 1500 or less we put the length , if 1536 or greater we put the type) 

the fragments are reassembeld by the reseiving Host



	7/ Flags (3 bits)

separated bits used to control/identify the fragnments

first : or bit 0 , is reserved and always set to 0
second: or bit 1 , is the DF-bit (Don't fragment) indicates that the packet should not be fragmented , and be sent full
third : or bit 2 , is the MF-bit (More fragments) set to 1 to indicate if there is more fragments to the packet, last fragment is 0
	, if the packet is not fragmented it is set to 0 



	8/fragment offset(13 bits)

keeps the possition of fragments 

to be reassembled right even if the fragments arrive out of order




	9/ TTL - Time to Live (8 bits)

if a packet is stuck in a loop between the Routers it can cause a huge traffic problem and Congestion

the TTL prevent this, a packet is dropped if the TTL reaches 0

the ideal Recommended TTL is 64 --->  01000000

each Router/Hop decreases the TTL by 1,  till it reaches the destination or gets Dropped



	10/ Protocol (8 bits)

indicates which protocol is used in the Payload

	UDP  - 17    0001 0001
	TCP  - 6     0000 0110
	ICMP - 1     0000 0001
	OSPF - 89    0101 1001
	.
	.

there are many protocols , these are the mmost common



 	11/ Header Checksum (16 bits)

used to track and check for errors in the L3PDU header

however it doesn't check for errors in the Payload , the encapsulated Protocols has their own checksum for data

like TCP and UDP



	12/ Source IP address (32 bits)  

the IP Address of the Sender



	13/ Destination IP Address (32 bits)

the IP Address of the Receiver





	14/ Options (0 - 320 bits)

an optional field 

if the IHL fiel is Greater than 5 , it means that the Options is Present

(this topic is off the CCNA exam, yo ucan read more about it )
